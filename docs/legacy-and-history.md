# Codex Wallpaper 0.7.0

## 冷啟動動畫

現有整合入口僅在 Codex 程序尚未運行時，全螢幕播放隨附 Dragon Codex Boot 動畫，同時啟動官方程式並預載桌布。Codex 已在背景、最小化或隱藏時，直接喚回原視窗，不播放動畫；側欄輔助程序不監測或觸發重播。播放中的同一程序會去重，動畫結束後再次真正冷啟動可立即播放。背景接入程序在 Codex 已退出時只等待，不自行重開。靜態背景確認套用後可交接，動態首幀稍後就緒時自動替換。Esc 可跳過動畫。動畫覆蓋所在螢幕及工作列，影片保持原比例；播放期間保留主視窗位置與大小，正常播完後將當次已核對的 Codex 主視窗最大化，再交回操作。Esc 跳過、播放失敗及等待逾時不執行最大化；背景叫回不受影響。原版圖示保留，動畫不出現在工作列或 Alt+Tab。

播放器為被動本機版本，不會自行開啟 Codex、掃描或替換捷徑。影片失敗時直接交還主介面，等待上限 30 秒。可在 `data/boot-animation.json` 設定 `{"enabled":false}` 停用，下次冷啟動生效。動畫、媒體及編譯檔在 `assets/boot-animation`，編譯使用 `scripts/build-boot-animation.ps1`；來源及素材說明見 `THIRD_PARTY.md`。

動畫播放期間隱藏右上角 Wallpaper 按鈕與側欄，即使 Codex 中途取得前景也不浮到動畫之上。依當次播放器的 PID、啟動時間與固定程式路徑判定；播放器結束或意外退出後自動恢復，保留原本的側欄開啟狀態。啟動請求尚未建立播放器的短暫隱藏以 2 秒為限，過期／損壞紀錄或重用的 PID 不會持續隱藏入口。

最小化期間暫停渲染與宿主介面檢查，還原後先等 500ms 穩定時間，再恢復輸出；正常休眠不觸發重新接入。輸出失敗會保留最後畫面並停止自動重試，從側欄調整設定或重試後才恢復。`logs/last-cold-launch.json` 另外保留冷啟動結果，避免被後續喚回記錄覆蓋。

Windows 桌布服務與本機控制插件。保留 Codex／ChatGPT 原有格局與配色，提供圖片、影片、WebWallGL 即時 Scene、六區材質及預設。程式與資料放在宿主安裝包之外。

## 整合啟動模式（2026-11-03）

已安裝版可執行 `app/scripts/install-wallpaper-entry.ps1`，將桌面與開始功能表的「Codex Wallpaper」捷徑改為直接開啟 Codex 並自動帶起桌布服務。這個模式不開獨立管理器或系統匣；設定沿用最小化左側的「◈ Wallpaper」與五分頁側欄。原版 Codex 安裝檔不變，其他未設定的入口也不變。

`app/scripts/install-codex-user-shortcuts.ps1` 會在桌面與開始功能表建立原版圖示的「Codex」整合捷徑，並修復指向同一官方套件舊版本的既有「ChatGPT」捷徑。原捷徑先備份；其他軟體或使用者修改過的入口會保留。執行同一腳本加 `-Restore` 可還原未被另外修改的入口。工作列已釘選整合入口時可繼續使用，不會直接修改 Windows 釘選資料。

啟動時先顯示原版視窗，再以同一條已驗證連線等候桌布就緒，最後整理捷徑圖示。等待期間不反覆建立 Node／PowerShell 驗證程序；連續點擊仍由啟動互斥避免重複執行。最近一次啟動摘要記錄於 `logs/last-launch.json`，不含聊天或連線憑證。

工作列／桌面入口叫回既有 Codex 時，優先使用短期宿主提示並重新核對目前 PID、啟動時間、官方程式路徑及根程序唯一性，直接呼叫原生啟用流程。提示五分鐘過期，版本切換、PID 重用、模糊目標或無效資料都回退官方套件重新探索；註冊身分變動不阻擋一般路徑。原生啟用元件已預編譯並核對來源／組件雜湊；真正冷啟動不先載入用不到的啟用元件。啟動處理中再次點擊，只叫回已存在的視窗，不重播動畫、不另開 Codex 或重複初始化桌布。摘要另記錄 `nativeRequestMs` 與 `hostHintUsed`，用於區分原生啟用請求及後續桌布準備時間。

既有宿主監視程序沿用原本每 30 秒的官方套件核對更新提示，不新增常駐程序或額外套件掃描；提示保留該次套件驗證時間，單純重寫不延長有效期。冷啟動確認沒有既有主程序後先開始動畫，再探索安裝資訊及啟動原版，讓畫面回饋與探索並行；預查失敗仍回到完整探索，並保留原有播放、預載與交接規則。

接入端點尚未出現時會標示 `HOST_ENDPOINT_PENDING`，在背景以退避方式重試，等待預算為 90 秒。逾時後停止自動嘗試，側欄顯示 `HOST_ENDPOINT_TIMEOUT` 並提供重試；不將啟動較慢判為永久不相容。程序路徑、啟動時間及本機端點歸屬仍須通過核對。桌布初始化失敗或執行環境缺失時，原版 Codex 仍可開啟，連線錯誤留在側欄與啟動摘要，不再彈出阻擋啟動的 Wallpaper 對話框。原版程式本身無法啟動時仍回報錯誤。

啟動流程會讓宿主探索／接入與控制服務的準備工作並行，私有目錄檢查與服務程序身分核對也同時進行；控制憑證仍須等兩者成功後才發布。背景服務剛啟動時，捷徑直接沿用等待客戶端的連線結果，不再重開另一組 Node／PowerShell 驗證程序。端點探索使用 Windows 原生 owner-PID TCP 表，每次重新讀取，保留 IPv4／IPv6 衝突及程序身分檢查；不可用時回退原有查詢。隨附查詢元件先行編譯，以雜湊核對原始碼與組件相符，避免每次啟動現場編譯。開發時可執行 `scripts/build-native-tools.ps1` 更新組件。

`logs/startup-timing.json` 保存設定、素材庫、控制服務、首次接入、首次套用與標題列入口就緒的耗時，供後續版本調整；不記錄聊天內容、憑證或素材路徑。原尺寸、完整效果、省電開關及既有播放偏好沿用。

主視窗判定會排除 Electron 無標題的 `Chrome_WidgetWin_0` 輔助視窗、工具視窗與有擁有者的視窗。冷啟動時等候實際主視窗，不會強制顯示內部輔助視窗。若過去版本已顯示這類空白視窗，下一次整合啟動會在確認正常主視窗存在後將它隱藏，不會關閉 Codex 程序。Wallpaper 按鈕、工作列分組與可見性監測使用相同的主視窗條件。連線尚未完成時啟動摘要為 `pending`，只有已確認套用或使用者停用桌布時才記錄 `completed`。

自動接入時，宿主端點核對與自有渲染程序預熱並行；只有已啟用、未暫停且選取受支援即時場景才預熱，實際場景仍等介面檢查通過後載入。預熱共用同一個瀏覽器啟動與能力驗證工作，不建立額外場景；沒有播放工作時依原有閒置期限釋放。圖片、靜態模式、普通未接入的宿主與 isolated 模式不會因此啟動渲染池。工作列圖示屬性在背景另行核對及套用，不阻擋桌布接入，也不重新搶焦點。

場景載入採用與 DSH 相同的備援順序：目前桌布上次成功畫面 → 作者預覽圖 → 原生底色。連線檢查期間先將有界限的候選圖片讀入記憶體；完成介面驗證後依序解碼，壞快取會回落到作者圖片。靜態圖片確認顯示後即可完成圖片接入，側欄標示「靜態背景已顯示，正在預載動態場景」。實際場景在背景準備，首幀解碼並確認套用後才替換圖片；失敗時保留靜態背景及重試入口。首個成功動態畫面立即保存，後續依原有期限更新快取。停用／退出會取消準備工作，預載不會更改使用者的播放偏好。

首次切換時，已開啟的普通 Codex 可能缺少連線端點。捷徑會顯示既有原版視窗，並在側欄保留需要重新啟動的提示；請自行儲存工作並正常完全退出，再由整合捷徑開啟。捷徑不自動安排退出後重開。若已接通，重複點捷徑會顯示既有視窗，不另開渲染工作階段。正常退出 Codex 後，桌布服務會在確認沒有待接回工作後結束。

捷徑原檔與雜湊備份在 `data/shortcut-backups`；同名但屬於其他程式的捷徑不會被覆寫。整合模式目前是既有安裝的升級入口；下述舊安裝器與 CMD 仍保留管理器流程，重新執行舊安裝器後應重新執行 `install-wallpaper-entry.ps1`。

本批已驗證服務模式、捷徑及正常退出後自動接回：狀態回報 `observed.applied=true`、playing，輸出 1920×1020，即時讀數約25FPS；仍待使用者確認視覺與操作體驗。不能把服務已啟動當成桌布已套用，仍以 `observed.applied` 及畫面確認為準。

## 舊版管理器安裝與啟動

建議解壓安裝包，雙擊「安裝CodexWallpaper.cmd」。由原始碼升級時，先執行 npm ci，再雙擊「安裝獨立桌布插件.cmd」；這個入口會帶入同資料夾內的0.5設定。既有獨立版安裝會保留新資料，不用重新匯入。

安裝完成後使用桌面／開始功能表的「Codex Wallpaper」，或本資料夾的「啟動CodexWallpaper.cmd」。管理器有自己的視窗和系統匣圖示；關閉視窗會留在系統匣，選「退出管理器」才結束。管理器退出會清除自身外觀，不關閉原版宿主。

日常可直接點 Codex 最上方「－」最小化按鈕左邊的「◈ Wallpaper」，開啟舊版五分頁側欄。按鈕與側欄是管理器自己的視窗，不修改 Codex 安裝包或聊天版面；跟隨視窗移動、縮放、最大化及最小化，切換至其他應用時隱藏。側欄沿用原本的 panel-dom.js／panel.css，使用已安裝的 WebView2，沒有網址列或另一個瀏覽器標題列。首次安裝只啟動系統匣與貼附入口，顯示完整管理器仍可用原捷徑。

定位優先使用原生標題列範圍；自繪標題列只查詢唯一「最小化／Minimize」按鈕的位置並快取，不讀取聊天。無法唯一核對時停止貼附，在管理器顯示 CAPTION_BOUNDS_UNAVAILABLE。這個入口不需要背景接入端點；背景尚未套用時仍可調整設定，側欄會顯示原因。

若目前視窗是從一般 Codex／ChatGPT 入口開啟，管理器可能顯示「需要由管理器啟動」。可點「退出後自動接回」，再自行儲存工作並從系統匣正常完全退出宿主；管理器會使用最新安裝路徑接回。它不會強制關閉目前聊天。

沒有安裝登入自啟；重新登入Windows後需開啟Codex Wallpaper。按鈕能顯示不等於背景已接通，請以側欄實際狀態為準。歷史0.6.0曾在Codex26.1027.3384.0接通並由使用者確認動態背景；當時1024×660來源、1536×816顯示區實測27.64解碼FPS。0.7.0的當前接入狀態與獨立效能測試另見VALIDATION.md。原生提問卡與聊天按鈕數變動不會單獨判為不相容，未知必要結構仍停止套用並報錯。

## 更新與狀態

2026-11-03連線修正：已接通時重用現有session，省去重複安裝掃描與native核對；每次顯示視窗仍核對實際程序與端口。宿主及可見性監視程序退出後會以退避方式補回；相同清單不重複觸發介面刷新。相同設定也不再於attach時重複套用。短測控制請求由一次約15秒降至三次約3.5–4.4秒，實際捷徑熱啟動約7.3–7.6秒，首次圖示維護較久；此讀數不代表所有場景冷啟動速度。

管理器將「希望啟用」和「確實已套用」分開顯示，核對目前程序、連線、介面契約、樣式與背景影格。程序結束或證據過期後，不把舊紀錄顯示成成功。

宿主更新後重新偵測。相同介面結構可沿用適配器，標示「結構相容，未列為人工驗證版本」；必要結構改變時保留原版，顯示錯誤碼與重試操作。不能保證每個未來版本或工坊特效都相容。

| 顯示 | 操作 |
| --- | --- |
| HOST_NEEDS_MANAGED_LAUNCH | 安排正常退出後接回 |
| ADAPTER_LAYOUT_MISMATCH | 保留原版，查看失敗檢查並更新適配器 |
| HOST_TRANSPORT_UNAVAILABLE | 這個宿主尚無已支援接入方式 |
| HOST_ENDPOINT_PENDING | 原版已啟動，桌布正在背景等待已核對端點 |
| HOST_ENDPOINT_TIMEOUT | 停止自動重試，Codex 可繼續使用；從側欄重試 |
| RENDERER_FAILED | 更換桌布或重試，管理器保持可操作 |
| SETTINGS_INVALID | 檢查設定或遷移備份，原始資料保留 |
| RUNTIME_MISSING | 檢查 Node、PowerShell 及 Edge |

目前適配的是 Windows Codex 安裝包內的 Codex／ChatGPT 模式。不同的獨立 ChatGPT 客戶端需另外確認傳輸與適配能力，未確認時不套用。

## 控制插件

本機插件為 codex-wallpaper-control@codex-wallpaper-local，顯示名稱 Codex Wallpaper。提供實際狀態、開啟管理器、啟用／停用、外觀設定、重新偵測及去識別診斷六個 MCP 工具，以及支援宿主中的控制面板入口。

插件狀態查詢不隱式開啟管理器。插件無法載入時，Windows 獨立視窗與系統匣仍能操作。插件更新後如需新聊天才能載入，工具與面板驗收會另記，不把安裝成功當成已連線。

另已宣告正式對話側欄入口，位置由宿主決定。新貼附按鈕固定在最小化左側，與正式插件及背景接入各自判定狀態；舊注入式入口仍保留供已接入的開發流程使用。背景不會因為按鈕顯示或設定已儲存就被標示為已套用。

更新時若 Windows 鎖住使用中的插件快取，安裝器保留同一來源的既有入口並回報 pluginRefreshPending；獨立管理器照常更新。下次宿主重新載入插件後使用新入口，不強制結束聊天。

## 桌布與材質

2026-11-03修正：移除左側清單在區域材質內重複疊加的底色，讓同一張背景延伸到整個視窗；保留選取列及原生文字。暫停／隱藏／關閉時改為每秒最多4次輪詢，靜態圖每秒2次，動態桌布頻率與解析度不變。狀態刷新重用同次確認結果，避免重複讀取宿主；Edge啟動使用相容重啟旗標保持可核對的程序身分。未宣稱播放中CPU或FPS已提升。

五分頁為桌布庫、畫面、材質、播放與預設。材質頁的「套用全視窗材質」涵蓋聊天、左欄、輸入框、頂欄、右側／編輯面板、設定／浮層；各區獨立控制底色、模糊及邊框。預設保留原生配色。

Scene 使用獨立、未登入的 Edge 與 WebWallGL3.0.0，JPEG92影格只保留最新一張，提供最多60FPS設定；實際速度依場景、解析度與硬體而異。圖片／影片保持來源比例。原生聊天版面與CSP維持原樣。

2026-11-01品質修正：新設定與重設播放改為1920×1080，已保存的手動解析度不被覆寫；本次使用者設定為1920×1020。Scene固定DPR、紋理及高品質後處理，停用自動降檔。合成器取幀不額外保留WebGL drawing buffer，後備擷取必須保持要求的完整尺寸，不能以模糊裁切影格當成成功。這些變更不代表已完成DSH全部功能或保證每張場景30FPS；目前實際接入與測量範圍見VALIDATION.md。

## 0.7.0 渲染池與快取

播放頁保留原來五分頁，增加「自動／共用／獨立渲染」、「跟隨視窗／手動尺寸」、貼圖快取及清理控制。自動模式先檢查自有 Edge 的多頁完整取幀能力，環境不支援才使用獨立渲染；明確共用模式會顯示錯誤。靜態圖片不啟動渲染器。

同一管理器共用一個未登入的 Edge、最多兩個內容頁與一個快取控制頁。準備工作序列化、只保留最新選擇；舊影格在新來源確認解碼前保留。沒有租約60秒後釋放自己的 Edge，profile 保留供下次使用。失聯會立即撤銷已套用證據，五分鐘最多自動恢復三次；耗盡後使用「重新連線」重試。

跟隨視窗使用 CSS 尺寸乘螢幕縮放倍率，超過1920×1080時等比限幅；手動數值仍保存。升級前的1920×1020等設定會保留為手動模式，切換模式才跟隨視窗。schema2 遷移前先以原始檔案 SHA256 建立一次備份，所有桌布、材質、配色及播放偏好保留。

WebWallGL 貼圖 payload 使用 Cache Storage，索引用獨立 IndexedDB；受控 Blob 總額最多512MiB，profile及瀏覽器其他資料另計。引擎與快取防護程式雜湊需通過實機資格才啟用。清理／關閉快取以 epoch 拒絕舊頁寫入；快取不可用時保持播放並顯示原因。影片和圖片不使用這個貼圖快取。

目前同Scene、1920×1020、high、JPEG92三組短測：共用／獨立解碼中位為26.28／25.45 FPS；Node加renderer的CPU約少2.6%，working set約多8%。空白接收頁與原版Codex分開驗證，不保證固定FPS或長期提速。DSH其餘功能仍依對照表分批處理，沒有宣稱全部移植。

## 資料與解除安裝

獨立安裝根為 %USERPROFILE%/.codex-wallpaper/：app 放程式、data 放設定及素材、runtime 放暫時工作階段、logs 放診斷。此位置避開 Windows 安裝包對 AppData 的重新導向；安裝器也以獨立程序建立捷徑及註冊插件。更新程式不覆寫 data。遷移0.5時先備份，保留桌布、閱讀位置、材質、收藏、預設及來源；不複製帳號或聊天資料。

解除安裝使用 app/scripts/uninstall-companion.ps1，會移除自身插件與捷徑並停止管理器，data 預設保留。先前程式版本放在 app.previous-*，解除安裝程式副本放在 app.uninstalled-*，供回復及人工清理。它不刪除工坊來源。

### 省電模式

在右上角「◈ Wallpaper」→「播放」開啟「省電模式（靜態圖片）」，以最後一幀或相同桌布的快取／預覽圖取代場景及影片，停止動態渲染。省電時不啟動場景預熱或縮圖渲染；關閉後恢復原尺寸與完整效果。原有即時渲染、手動尺寸及 FPS 偏好均保留。畫質分級選單已移除，舊畫質設定會遷移為完整效果；沒有可用靜態圖時顯示原生底色。

啟動時會先顯示目前桌布最後成功輸出的快取圖片，再接上動態場景。更換桌布時不會借用另一張桌布的啟動畫面。


### 場景即時渲染

選中 Scene 桌布後，在「◈ Wallpaper → 播放」可開關「場景即時渲染」，並選擇 15／30／60 FPS。選擇檔位會同步引擎和背景更新頻率；實際幀率仍受硬體與場景複雜度影響。舊的自訂 FPS 值會保留，側欄會顯示目前上限。

關閉後立即停止並釋放該場景的 WebGL 頁面，顯示最後成功畫面；重新開啟或切換來源時，使用符合目前桌布 ID 的快取或安全預覽圖。沒有可用畫面時顯示原生底色並在側欄提示。關閉狀態會保存，重啟時不會為產生靜態圖而偷偷啟動場景引擎。圖片與影片沿用原本播放方式。
